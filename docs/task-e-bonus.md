# Task E (bonus) — Шлях 2: автоматична перевірка доступності

**Інструмент:** [axe-core](https://github.com/dequelabs/axe-core) 4.x,
запущений через headless Chromium (Playwright) — обидва тимчасово
встановлені (`npm install --no-save`, не в `app/`), без правки
`package.json` цього репо. Сценарій піднімав `npm run dev` (`localhost:3080`),
відкривав сторінку, вставляв `axe.min.js` через `page.addScriptTag`, і
викликав `await axe.run()` у чотирьох станах:

| # | Користувач | Фільтр | Кольорова схема |
|---|---|---|---|
| 1 | Оля | Активні | light |
| 2 | Оля | Активні | dark (`page.emulateMedia({ colorScheme: "dark" })`) |
| 3 | Оля | Архів (порожній стан) | light |
| 4 | Тарас | Активні | dark |

**Що знайшло:**

- **[serious] `color-contrast`** — у **темній** кольоровій схемі всі кнопки
  (`Додати`, фільтри, `Архівувати`, `Видалити`) мали контраст **1.07–1.14**
  замість потрібних **4.5:1**: білий текст на майже білому фоні. Причина —
  `:root { color-scheme: light dark; }` у `style.css` змушує браузер
  застосувати темну тему до нативних кнопок (білий текст за умовчанням), але
  фон сторінки (`<body>`) ніде явно не перефарбовувався в темний — залишався
  світлим. Тобто кнопки й фон розходились по темі.
- **[moderate] `landmark-one-main` / `region`** — у всіх чотирьох станах:
  на сторінці не було жодного `<main>`, і весь контент (форма, фільтри,
  список нотаток, порожній стан) лежав поза лендмарками — для користувачів
  скрінрідерів це означає «нема швидкого переходу до основного контенту».

**Що полагодили, а що лишили і чому:**

- **Полагодили обидва.** У `app/public/index.html` обгорнув форму, фільтри,
  список і порожній стан у `<main>`. У `app/public/style.css` додав
  `body { background: Canvas; color: CanvasText; }` — системні CSS-кольори,
  які самі стежать за `color-scheme` і тепер реально перефарбовують фон
  сторінки в темний разом із кнопками, а не лишають його світлим.
- Повторний прогін axe у всіх чотирьох станах після фіксу: **0 порушень**
  у кожному. `cd app && npm test` — 15/15 зелені, наскрізна перевірка в
  браузері (архівування → `reload()` → стан вижив) також не зламалась.
- Нічого не лишив без фіксу — обидва знайдені пункти були реальними й
  дешевими для виправлення (кілька рядків CSS/HTML, без нової залежності в
  самому застосунку).

**Чи збігається знайдене з типовими дефектами зі слайдів** (контраст, alt,
підписи полів, порожні кнопки/посилання, мова документа)?

Частково. **Контраст** — це саме той типовий дефект зі слайдів, і axe його
знайшов, але не в тому місці, де я б очікував (не в звичайній світлій темі,
де я вручну перевіряв руками й через accessibility snapshot — там усе було
ок), а в темній, яку я взагалі не тестував руками. Це підтверджує сумнів,
який я сам зафіксував у `docs/ai-mistakes.md`: «контраст перевірявся тільки
в світлій темі за замовчанням». **Alt-тексти й порожні посилання** — не
застосовно, на сторінці немає `<img>` чи `<a>`. **Підписи полів** — форма
додавання нотатки (`#title`, `#body`) axe не позначив, хоча в неї немає
явного `<label>` — лише `placeholder`; axe це не завжди ловить як
порушення (`placeholder` рахується частковою заміною), тож ручна перевірка
тут усе ще потрібна, автоматика не покриває це повністю. **Мова
документа** — `<html lang="uk">` присутній, тут усе гаразд.
